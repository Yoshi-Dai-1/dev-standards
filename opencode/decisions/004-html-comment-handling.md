# ADR 004: テンプレート内 HTML コメントの取り扱い

**日付**：2026-07-16  
**状態**：採用

---

## 状況

テンプレートファイル（`.md.template` 等）に記述された HTML コメント（`<!-- ... -->`）が、AI エージェントによる `write_file`（全上書き保存）時に自動削除される問題が発生した。これにより以下が失われる：

- 次回更新時の AI 向け指示（例：`<!-- 新しい月は右端に追加 -->`）
- 初回セットアップ時のガイド
- ファイル構造の意図を伝える注釈

一方で、すべての HTML コメントを一律保存すればよいわけではない。初回限りで不要になるコメントや、可視テキストで代替可能なコメントも存在する。

## 検討した選択肢

| # | 選択肢 | 評価 | 選ばなかった理由 |
|---|--------|------|------------------|
| 1 | HTML コメントをすべて削除し、可視テキストに統一 | ❌ 却下 | テンプレートが冗長になる。コピー先ファイルに残るものは不可視であるべき |
| 2 | すべての HTML コメントを `write_file` で維持する | ❌ 却下 | 初回限りの消費型コメントまで残り、クリーンアップが別途必要 |
| 3 | 3分類 + ルールベースで扱いを変える（本件） | ✅ 採用 | — |

## 決定

HTML コメントを以下3種に分類し、それぞれ異なる扱いとする：

### 分類

| 分類 | 性質 | 扱い | 例 |
|------|------|------|----|
| **挿入位置マーカー** | 値の記入位置を示す。可視テキストで代替可能 | **冗長 → 削除**<br>（既存の可視ルールでカバーされている場合） | `<!-- 新しい月を右端に追加する -->` が更新ルールに重複する場合 |
| **消費型コメント** | 初回記入時に AI をガイドする。完了後は不要 | **HTML コメントとして維持**<br>セクション削除やテンプレートコピー時に自然に除去される | AGENTS.md の `## 初期セットアップ` 内のコメント<br>project-definition-guide.md のテンプレート内コメント |
| **永続注釈** | ファイル構造や更新ルールとして恒久的に必要 | **可視テキストに変換**<br>形式は `【...】` またはセクション内プレーンテキスト | 列の並び・記入ルール・注意事項 |

### 変換ルール

```
挿入位置マーカー:
  可視ルールが既に存在 → 削除（冗長）
  可視ルールがない     → 可視テキストに変換

消費型コメント:
  HTML コメントのまま維持
  テンプレートコピー時やセクション削除時に消えることを前提とする

永続注釈:
  【...】 またはプレーンテキストに変換
  HTML コメントのままにしない（write_file 時に AI に削除されるリスクあり）
```

### 分類の判断フロー

```
1. このコメントは初回限りの指示か？
   Yes → 消費型コメント → HTML コメントのまま維持
   No  → step 2

2. このコメントの内容を既存の可視ルールがカバーしているか？
   Yes → 挿入位置マーカー（冗長） → 削除
   No  → step 3

3. このコメントは write_file で削除されても困らないか？
   Yes → 消費型コメント → HTML コメントのまま維持
   No  → 永続注釈 → 可視テキストに変換
```

### 実装の注意

- **`_fill-guide.md`** で明示しない限り AI は HTML コメントを保持しない。保存が必要なセクションには preservation ルールを記述する
- preservation ルールには**削除が許容されるコメントの条件**も併記する（例：「`## 初期セットアップ` 内は削除してよい」）
- 可視テキストへの変換形式は、文脈に応じて `【...】` 記法とプレーンテキストを使い分ける
  - `【...】`: システムレベルの補足説明（テンプレート構造の意図等）
  - プレーンテキスト: 更新ルールなど、ユーザー向け指示と一体化すべき情報
- 消費型コメントが配置されるセクションは、完了後にそのセクションごと削除されることを設計で保証する（例：AGENTS.md の `## 初期セットアップ`）

## 結果・影響

良い影響：
- AI が write_file 時に誤削除する問題が、`_fill-guide.md` の preservation ルール + 可視テキスト化の併用で解決される
- コメントの種類ごとに期待動作が明確になり、設計判断の再現性が向上する
- 分類フローがあれば新規テンプレート作成時も同じ基準を適用できる

悪い影響・トレードオフ：
- 可視テキストに変換した分、ファイルの行数が増える
- 消費型コメントと永続注釈の境界判断が人によってブレる可能性がある
- 消費型コメントの除去はセクション削除に依存するため、セクション削除しなかった場合に残存する
